## Context

当前开工条件平台已经具备平台拥有的 pilot task、checklistDefinition、checkItems、humanReviewQueue、events、reportAsset 和逐文件资料对象。A+B 完成后，资料文档库和待核查项已经有了真实输入，但操作路径仍然偏散：

- 资料预览、待核查项审核、人工复核完成、最终报告查看没有稳定收束在一个选中任务工作台里。
- 右侧进度区虽然有任务状态和事件，但最终落点仍偏诊断化，离用户要的“像智能体回复一样输出最后 Markdown 报告”还有距离。
- 前端已有删除历史、完成人工复核、生成报告等契约，但实际工作流和 UI 组织还不够一致。

本轮继续只做开工条件平台，不触碰施工审查平台。

## Goals / Non-Goals

**Goals:**

- 将选中任务详情收束为一个单任务工作台，支持 `列表 -> 文件预览 -> 待核查项复核 -> 最终报告` 的连续切换。
- 让右侧进度区以平台 run events 为事实源，表现成智能体时间线，并在人审完成后展示最终 Markdown 报告。
- 让人工复核完成成为唯一需要用户显式推进的暂停节点，其余步骤保持平台自动流转。
- 保持历史任务的创建、删除、选中和返回新建审核的状态一致。

**Non-Goals:**

- 不新建 OCR/知识库/工作流 provider 能力。
- 不重做整个 shell 导航结构，也不扩展到施工审查平台。
- 不重写报告导出或归档模型，只复用现有 `reportAsset` 与 `markdownContent`。

## Decisions

### 1. 选中任务详情继续使用单工作台模式，而不是拆回多个页面

决定：保留当前 `list / preview / review` 的工作台模式，并新增“报告完成后的主展示落点”，而不是把人审和报告重新拆回独立页面。

原因：

- 用户已经明确要求点击资料库文件、点击待核查项、完成人工复核后都围绕同一个选中任务进行。
- 这样最贴近成熟审核产品的连续工作流，减少上下文丢失。

### 2. 人工复核完成采用“前端显式收口 + 复用既有后端动作”模式

决定：当所有阻塞人审项都已关闭时，工作台主按钮执行“完成人工复核”，随后继续调用既有报告生成动作，把结果刷新回当前任务。

原因：

- 后端已经有 `completeOpeningConditionPilotHumanReview` 和 `generateOpeningConditionPilotReport`，当前最有价值的是把它们串成一个用户可理解的闭环，而不是再新发明状态机。
- 这保持“只有一个需要用户处理的暂停节点，其余由平台自动完成”的产品节奏。

备选：

- 让后端 completion 接口自动生成报告：能更省前端步骤，但会把现有契约改大，本轮先不扩。

### 3. 右侧进度区以事件时间线 + Markdown 报告为主，不以 dense diagnostics 为主

决定：右侧优先展示事件时间线和最终 `reportAsset.markdownContent`，而 package diagnostics、delivery package、MVP acceptance 等留作辅助折叠信息或次级区块。

原因：

- 用户明确指出当前“报告详情页数据堆叠非常丑”，目标格式应更像 AI 最终回复。
- 平台内部诊断仍有价值，但不该压过最终交付结果。

### 4. 历史任务交互继续以当前选中任务为单一事实源

决定：新建审核成功后立即选中新任务；删除当前任务时清空当前选中；返回新建审核时不丢失当前工作区上下文，只切回无选中任务的首页。

原因：

- 这能直接修复用户反复遇到的“任务创建后不显示、删除后细节还挂着、进了任务详情后回不去新建审核”的操作断裂。

## Risks / Trade-offs

- 右侧从 dense diagnostics 改成 Markdown 主视图后，部分内部字段会变得更深一层可见
  - 缓解：保留辅助诊断区，但主视图降噪。
- 单工作台模式会让 `productWorkspacePages.tsx` 继续偏大
  - 缓解：本轮优先在现有结构里收口状态机，不趁机做大拆分。
- 串联“完成人工复核 -> 生成报告”时，如果任一动作失败，用户可能感知为一步失败
  - 缓解：保留分步错误提示，说明是 completion 失败还是 report 失败。

## Migration Plan

1. 先收口 spec，明确选中任务工作台和 Markdown 报告为主的交互契约。
2. 在现有前端工作台模式里补齐 review/complete/report 连续动作。
3. 将右侧进度面板切换为事件时间线 + Markdown 报告输出。
4. 修正历史任务创建/删除/返回首页的选中逻辑。
5. 用轻量 smoke 验证任务详情主闭环。

## Open Questions

- 是否需要在本轮把右侧辅助诊断区直接做成折叠面板，还是先保留次级静态区块即可。
- Markdown 报告是否需要在本轮补一键复制/导出入口，还是先只完成内联展示。
