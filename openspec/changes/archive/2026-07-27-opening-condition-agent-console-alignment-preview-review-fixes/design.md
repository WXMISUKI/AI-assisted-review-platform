## Context

开工条件平台已经把默认入口收敛到“新建审核 -> 上传资料 -> 任务详情 -> 人工复核 -> 报告”的低噪音工作台，但当前实现里仍有三处断链：

1. 首页容器依赖上层高度传递，工作区滚动容器变化后，新建审核页不再稳定居中。
2. 资料包清单同时存在 source archive 和 inventory entry 两层对象，当前视图在部分刷新路径里仍可能拿到旧任务快照或 manifest-only 条目，从而错过已生成的 derived asset。
3. 人工复核详情页动作虽然会发请求，但当前任务与任务列表的去重优先级会让旧快照覆盖新结果，导致界面看起来“没反应”。

## Goals / Non-Goals

**Goals:**
- 恢复新建审核页的居中和自适应高度表现。
- 让资料包清单优先命中逐文件派生资产，并对无法内联预览的历史/不支持条目提供清晰回退说明。
- 让人工复核动作提交后立即更新当前任务、任务列表和详情页上下文。
- 用轻量 smoke 固定这些边界行为。

**Non-Goals:**
- 不重写上传链路或 ZIP 拆分算法。
- 不引入新的预览组件栈或外部服务。
- 不扩展到施工审查平台或其他产品面。

## Decisions

### 1. 通过工作区内容容器和智能体页双层约束恢复居中
- 选择在 `opening-workspace-content` 和智能体页容器上补足宽高、对齐和 margin 约束，而不是只给首页单个子块加绝对定位。
- 原因：问题来自父子层级的可用高度传递，双层修复更稳定，也不会影响任务详情页的滚动行为。

### 2. 当前任务视图优先使用最新任务快照
- 任务工作台会优先使用 `openingPilotTask` 这份当前任务事实，再合并历史列表，而不是让 `openingPilotAllTasks` 中的旧副本先占位。
- 原因：人工复核、报告生成和逐文件预览都依赖最新任务事实；如果旧快照优先，会出现按钮点击后状态不变、已生成派生资产却仍走 fallback 的假象。

### 3. 资料包清单预览坚持“derived asset first, archive fallback second”
- inventory entry 一旦存在 `derivedObjectRef`，预览必须优先走该对象。
- 如果条目只有 manifest，没有派生对象，则展示明确原因，并回退到原始 ZIP 打开链接；ZIP 本体继续视为资料包对象，不伪装成可内联预览文件。
- 原因：这与后端 packet item assets 的设计一致，也最贴近用户对“逐文件预览”的预期。

### 4. 人工复核动作后同步更新当前任务与任务列表
- 决策成功后同时更新 `openingPilotTask`、`openingPilotAllTasks`、`openingPilotWorkspaceTasks`，必要时保留当前详情上下文。
- 原因：这是当前“按钮点了没反应”的最短修复路径，不需要重做页面状态机。

## Risks / Trade-offs

- 任务列表优先级调整可能暴露其他依赖旧排序的视图 → 用现有 smoke 补充当前任务优先和人工复核回写断言。
- 布局修复若过度约束高度，可能影响小屏滚动 → 保留 `overflow: auto`，只修正最外层对齐和最小高度。
- manifest-only 条目仍然无法真正内联预览 → 明确提示为能力边界，不伪造成功状态。

## Migration Plan

- 本次为前后端同仓轻量修复，无需数据迁移。
- 历史任务若本身没有逐文件派生资产，仍按 manifest-only 提示处理。
- 若修复后发现个别旧任务列表仍缓存旧快照，刷新当前任务接口即可回正。

## Open Questions

- 无阻塞性开放问题；本轮按平台内置编排和现有 ZIP 资产化边界落地。
