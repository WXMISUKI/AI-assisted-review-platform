## Context

当前开工条件页面的业务事实已经基本符合 MVP，但默认组件仍把新建审核、审查范围、上传动作、历史记录和高级闭环信息作为多个同级面板渲染。参考云工案截图的核心不是复制品牌，而是复制信息架构：左侧是产品导航和历史，中央只有一个明确的新建任务入口。

## Goals / Non-Goals

**Goals:**

- 让用户进入平台后第一眼只看到一个明确动作：选择审查内容并上传审核资料。
- 保留当前项目选择和左侧历史审核记录。
- 让上传弹窗和现有真实三资料 bootstrap 逻辑继续复用。
- 让首页空状态不显示任务详情、指标台账或高级治理信息。
- 保持桌面端居中布局，并在窄屏下自然收缩。

**Non-Goals:**

- 不改后端 API、任务状态机或报告生成。
- 不改变资料完整性/合规性业务语义。
- 不实现真实文件预览器。
- 不删除任务详情中的高级闭环信息，只改变其默认入口位置。

## Decisions

1. **默认首页采用单一中央入口。**
   - `OpeningConditionObjectOverviewProductizedPage` 在无选中历史任务时只渲染一个 `opening-agent-chat-home`。
   - 标题、审查内容和上传入口形成一个垂直阅读顺序。
   - 历史任务仍由 shell 左侧渲染，避免主区重复。

2. **上传仍使用现有弹窗。**
   - 中央入口按钮只负责打开 `uploadModalOpen`。
   - 三类文件门禁和 `bootstrapOpeningConditionPilotTrial` 不重写，防止 UI 变更破坏真实链路。

3. **项目卡片只保留选择器。**
   - 保留角色和“当前施工项目”标签。
   - 删除选择器下方重复项目名称 `p`，项目名称只在 select 中显示。

4. **通过 CSS 降低视觉噪声，不引入新设计系统。**
   - 复用现有语义色、边框、surface 和按钮 token。
   - 中央入口使用浅色背景、细边框和单个蓝绿色动作色，避免增加新的全局颜色。

## Risks / Trade-offs

- [历史任务用户无法在首页主区看到摘要] → 左侧历史记录继续显示标题和进度，点击后进入详情。
- [高级台账入口不再首屏可见] → 保留在任务详情的高级折叠区，由任务详情进入。
- [截图尺寸差异造成视觉偏差] → UI smoke 验证结构边界，实际布局使用响应式 CSS，不做像素级硬编码。

## Migration Plan

1. 创建并验证本 change 的 proposal/design/spec/tasks。
2. 删除默认首页多面板 JSX，替换为中央单入口 JSX。
3. 删除项目选择器重复 `p`，补充中央入口样式。
4. 扩展 UI smoke 并运行 `npm run typecheck`、`npm run smoke:opening-condition:ui`。
5. 同步主 spec 并归档 change。
