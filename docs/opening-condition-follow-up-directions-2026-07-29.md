# 开工条件平台后续完善方向

更新时间：2026-07-29

本文件记录最近几轮讨论中仍需继续推进的问题，并按“最能推进项目、最有价值、最能快速投产”的顺序拆分。当前窗口只覆盖开工条件平台，不纳入施工方案审查平台改动。

## 第一批：任务台账与异步编排反馈

状态：本批已进入 `opening-condition-async-task-ledger-feedback` 实现。

- 新建审核后必须创建新的 run-specific task id，不能覆盖历史审核记录。
- 点击开始解析后，平台先完成对象上传和任务落账，弹窗关闭，左侧历史审核记录立即出现新任务。
- 新任务使用圆形进度指示，详情页显示平台工作流事件，后台继续执行资料匹配。
- 前端只轮询平台任务事实，不直接调用 MaxKB/OCR provider，也不伪造 workflow 结论。

## 第二批：人工复核详情工作台

- 点击资料文档库或待核查资料项时，预览/复核详情应替换整个 `opening-agent-detail` 工作区，避免嵌套在左侧小面板里导致看不清。
- 待核查资料项需要展示所有从用户核查表提取出的资料核查项，不应把合同/资质依据误当作待核查项。
- 复核详情右侧应说明为什么需要人工判断：当前核查模式、缺少哪些文件、哪些内容事实未证明、是否存在主数据授权缺口、是否存在视觉断言不确定。
- 接受、拒绝、修正、延期后必须写入平台人工复核决策账本，并刷新对应项状态。

## 第三批：报告事实整合

- 最终 Markdown 报告应直接在智能体处理进度/结果区域输出，而不是堆叠成复杂详情页。
- 报告的不符合项清单必须来自平台 checkItems、evidence、humanReviewQueue 和人工补充意见。
- 若本次只选择资料完整性核查，报告必须明确“未进行深度合规审查”，不能假装已经完成法规/内容合规判断。
- 法规依据和整改建议的大模型生成暂不与本批混做，后续单独进入“法规整改生成”批次。

## 第四批：资料资产与预览能力

- ZIP 资料包需要继续强化逐文件资产化、逐文件预览和旧数据 fallback 说明。
- 对旧资料包中没有独立对象的 manifest-only 条目，只能提示无法预览，不能把源 ZIP 当成该子文件打开。
- 超大 PDF 深度拆页、OCR 定位、页码跳转、标注预览属于后续专项，不与当前台账/异步反馈批次混做。

## 第五批：内容准确性与 RAG 辅助验证

- 合同/资质依据是主依据和上下文，不是待核查项。
- 文件内容准不准应通过平台已发布依据、主数据、资料包内容事实、人工复核和 provider/RAG 检索摘要共同辅助判断。
- MaxKB/OCR 仍是 provider：返回检索命中、摘要、置信度和来源，不拥有任务状态、人工结论或报告资产。
- RAG 质量评估、provider 同步状态、召回证据质量后续单独推进，不阻塞当前单项目试点闭环。
