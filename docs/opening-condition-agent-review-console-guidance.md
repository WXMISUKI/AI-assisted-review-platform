# 开工条件核查智能体交互指导

## 背景

真实样本试跑反馈表明，开工条件核查平台当前默认页面暴露了过多内部台账、轮次对比、证据治理和资产状态。它们对平台闭环有价值，但不适合作为首次进入业务平台时的主交互。

本指导文件用于约束后续开工条件平台交互改造：默认体验应接近成熟审核产品的“新建审核 -> 上传资料 -> 查看进度 -> 预览文件 -> 输出报告”路径，让监理或试跑人员可以直接上手。

## 产品定位

开工条件核查默认页面不是内部治理驾驶舱，而是开工材料审核智能体。

默认用户目标：

- 选择当前施工项目或审查对象。
- 创建一次新的开工条件核查。
- 上传合同/资质依据、资料核查表、核查资料包三类材料。
- 查看智能体处理进度。
- 在任务详情中左侧查阅资料，右侧查看核查进度和最终报告。

后台事实仍由平台拥有：任务、依据、主数据、证据、人工复核、报告和归档状态必须继续来自平台后端记录。Dify 或其他工作流只作为执行适配器或提示词来源，不作为前端持久事实源。

## 默认信息架构

### 左侧导航

左侧应保持低噪音：

- 当前项目卡片，可先 mock 项目/施工对象切换，例如“8标主线预制下部结构”。
- `新建审核` 作为主按钮。
- `历史审核记录` 作为当前项目下的任务列表。

人工复核、报告归档、资产治理、整改对比等能力仍可保留，但应通过任务详情、报告页或高级入口进入，不应在默认首屏铺开。

### 新建审核首页

主区域标题固定为 `开工条件核查智能体`。

审查内容选择：

- `资料完整性`：必选，默认选中，不允许取消。
- `资料合规性`：可选，表示后续需要调用工作流/子智能体或后端深度审查能力。

页面主体采用对话框式入口，左下角提供 `上传审核资料`。

### 上传资料弹窗

弹窗以三行资料清单组织：

- `合同/资质依据`
- `资料核查表`
- `核查资料包`

每行右侧提供上传按钮。三类资料都选择并上传成功后，`开始解析` 才可点击。

点击 `开始解析` 后，平台创建开工条件核查任务，左侧历史记录新增任务项，任务标题优先使用资料核查表文件名，并显示圆形进度。

### 任务详情

任务详情采用左右分栏：

- 左侧：资料文件列表和文件预览区域。文件列表来自平台已入库对象，包括合同/资质依据、资料核查表、资料包及后续拆分出的文件。MVP 可先展示对象摘要和存储引用，后续再接真实 PDF/DOCX 预览器。
- 右侧：智能体进度、审核状态和最终报告。进度语义应贴近工作流，例如解析核查表、整理核查项、拆分资料包、逐文件审核、生成报告。

## 审核逻辑边界

前端不得自行编造审查结论。

资料完整性审查可以展示“文件是否齐全、核查项是否被整理、资料包是否形成清单”等平台已有事实。

资料合规性审查必须来自以下来源之一：

- 开工条件核查工作流中的大模型提示词和结构化输出。
- 后端规范化后的 check items、evidence、human review、report findings。
- 已确认的规则、依据版本、主数据和人工复核结果。

如果只选择 `资料完整性`，最终报告可以按统一报告结构输出，但问题描述应明确“未进行深度合规审查”或“仅完成完整性核查”，不能假装已经做过内容合规判断。

如果同时选择 `资料合规性`，报告中的深入问题说明必须来自工作流/后端深审结果；前端只能渲染这些结果，不应根据文件名、静态 mock 或本地硬编码生成深审结论。

## MVP 改造优先级

第一优先级是把默认入口降噪：

1. 首屏改为智能体审核入口。
2. 上传三资料形成一个自然任务创建动作。
3. 历史任务按当前项目展示，带进度。
4. 任务详情形成“左文件、右进度/报告”的主工作区。
5. 现有台账、轮次对比、资产治理等内容转为二级或高级信息，不作为首屏主内容。

第二优先级才是增强真实预览、深度合规子智能体、实时流式进度和更完整的历史对比。

## 验收口径

一次开工条件真实样本试跑应能在默认路径完成：

1. 进入平台后看到 `开工条件核查智能体`，而不是指标台账堆叠。
2. 用户知道资料完整性必选，资料合规性可选。
3. 用户通过一个上传弹窗提交三类资料。
4. 提交后历史记录出现新任务，并能看到进度。
5. 点击任务后可查看资料列表、资料预览区、智能体进度和最终报告区域。
6. 报告结论的深度与所选审查内容一致，不出现前端伪造的深审判断。
